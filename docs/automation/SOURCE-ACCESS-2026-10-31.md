# ავტომატური კვლევა — წყაროების წვდომა და პირველი მოცულობა

შედგენილია 2026-10-31, მომხმარებლის Asia/Tbilisi თარიღით. ოფიციალური საჯარო
დოკუმენტაცია წაკითხულია ამ სამუშაოში; ანგარიშის დამატებითი რეგისტრაცია,
ფასიანი API მოთხოვნა, გამოწერა, scraping ან მონაცემთა ბაზის მიგრაცია არ შესრულებულა.

## პირველი ავტომატური ნაკადის მკაფიო მოცულობა

**შემდეგი შესაქმნელი ფუნქცია:** ერთი მფლობელის მიერ გაშვებული, bounded research batch.
იგი ჯერ არ არის იმპლემენტირებული ამ დოკუმენტაციის ცვლილებით.

1. მფლობელი ირჩევს საძიებო ფრაზას, ბაზარს, ზუსტ ვარიანტსა და დანიშნულებას.
   პირველი გაშვება მაქსიმუმ 3 კანდიდატზე; CJ-ის არსებული search მაქსიმუმ 20 შედეგს აბრუნებს.
2. სისტემა აგროვებს CJ ვარიანტის/მარაგის/მიწოდების მონაცემებს არსებული cooldown-ით;
   მარშრუტს, ვალუტასა და freshness-ს ინახავს. ვერ მიღებული ეტაპი blocked/failed-ად ჩანს.
3. eBay კავშირის არსებობისას შეაგროვებს ერთ გვერდს შეთავაზებების pending რიგში.
   წვდომის გარეშე ეტაპი blocked იქნება; ალტერნატივაა ნებადართული import/ხელით დაკვირვება.
4. ნაპოვნი შეთავაზება თავისთავად EXACT, მოთხოვნის მტკიცებულება ან დადასტურებული
   გასაყიდი ფასი არ გახდება. ვარიანტის/pack/condition/shipping/tax შედარება ცალკე რჩება.
5. შეფასების წესები გამოყოფს: მონაცემები აკლია / შესადარებელია გადასამოწმებლად /
   სრული შეყვანების საფუძველზე შეფასებული ეკონომიკა. უცნობი CAC/გადასახადი ნულით არ შეივსება.
6. შეკრებილი პაკეტის AI-ში გაგზავნა ცალკე თანხმობითა და არსებული ლიმიტებით ხდება;
   თანხობრივი ბიუჯეტის/საჯარო უფასო ტარიფის დაუდასტურებლად ფონურად არ ჩაირთვება.
7. შედეგად მომხმარებელი ხედავს წყაროებიან შედარებას და გამოტოვებულ ეტაპებს;
   არა მოგების გარანტიას. Stop, duplicate launch, partial failure და resume წესები შემოწმდება.

ამ ნაკადის საწყისი ვერსია მოთხოვნას UNKNOWN-ად დატოვებს, თუ მოთხოვნის რეალური
წყარო არ გვაქვს. Google Trends-ის წვდომის ლოდინი ტექნიკურ ნაკადს არ აჩერებს,
მაგრამ "მოთხოვნადი პროდუქტების ავტომატური პოვნა დადასტურებულია" ვერ ითქმის.

## შესრულების საზღვარი და ვადები

მოცულობა იყოფა სამ შემოწმებად სამუშაო ნაწილად:

1. batch-ის ეტაპები/მდგომარეობები და CJ-ის არსებული ოპერაციების დაკავშირება;
2. eBay pending შეგროვება ან მკაფიო blocked რეჟიმი და შედარების ფილტრები;
3. calculator/AI მიმოხილვა, Stop/partial failure/duplicate launch შემოწმებები და მომხმარებლის პილოტი.

კალენდარული ვადა ამ აუდიტით დადასტურებული არაა: eBay-ის დამტკიცებასა და წყაროების
პირობებზე კონტროლი არ გვაქვს. არც თანხობრივ ბიუჯეტს და არც ფასიან წვდომას არ ვირჩევთ
მომხმარებლის ნაცვლად. თუ persistent batch state-ს ახალი ცხრილები დასჭირდება,
ჯერ ზუსტ schema ცვლილებას მოვამზადებთ და მიგრაციამდე მფლობელის თანხმობას დაველოდებით.

## აუდიტის შედეგი

პირველი ტექნიკური მოცულობა განსაზღვრულია: **CJ → შეთავაზებების შეგროვება/blocked →
წყაროებიანი შეფასება → თანხმობით AI**. ყველა კონკურენტის, მოთხოვნისა და მომგებიანობის
სრული ავტომატური დადასტურება ხელმისაწვდომი წყაროებით ჯერ არ არის დასაბუთებული.
